# ADR 0022: 工程规范作为强制约定

- 状态: Accepted
- 日期: 2026-08-12
- 关联: docs/STANDARDS.md

## 背景

仓库在实现前已定架构与里程碑。若缺少统一编码、分层与模块通讯约定，M1 起易出现循环依赖、三方泄漏与不可诊断错误。

## 决策

1. 以 [STANDARDS.md](../../STANDARDS.md) 为编码、架构、模块通讯及其它工程约定的 **强制基线**。  
2. 冲突时优先级：**ADR > STANDARDS > 口头约定**。  
3. M1 起 PR 对照规范自检；实现阶段再补 clang-format / CI 钩子。  
4. 规范修订须改 STANDARDS（必要时新 ADR）并在 PR 说明。

## 后果

- 优点：协作一致、可审查。  
- 代价：早期需克制「图省事打洞」。

## 学习提示

1. 先看依赖方向与通讯优先级，再写功能。  
2. 换三方只动 adapters，是规范而非可选风格。
