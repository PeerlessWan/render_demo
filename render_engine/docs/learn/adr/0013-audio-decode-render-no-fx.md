# ADR 0013: 音频层仅解码与输出；明确不做特效

- 状态: Accepted
- 日期: 2026-08-12
- 关联: CH18c, engine/media（Audio）；PLAN 风险锁死

## 背景

引擎需要播放音频资源（独立文件或与视频同容器音轨），并与视频纹理形成基础媒体能力。完整游戏音频中间件（总线、效果器、空间化）成本高，且偏离「以渲染为中心」的定位。

## 决策

1. 提供 **AudioDecoder → AudioClip → AudioSource → AudioOutput** 薄层（经抽象，三方可替换）。  
2. 能力限于：解码、缓冲、播控（播/停/循环/seek）、音量、多源 **增益混合**、可选与视频 **基础时钟对齐**。  
3. **明确不做音频特效（产品硬边界，非延期）**：  
   - 无 EQ / 压缩 / 混响 / 合唱等 DSP 效果器  
   - 无效果器总线 / 调音台产品化  
   - 无 HRTF / 完整 3D 空间音频 / 多普勒  
4. 音频输出不经过图形 RHI；与 `VideoTexture` 并列于 `media/`。  
5. 上层若需特效：在**游戏/中间件工程**自行接入，不进入本引擎范围。

## 备选方案

- 接入完整 FMOD/Wwise —— 能力强，依赖与授权重，且会把特效栈绑进引擎，否决。  
- 完全不做音频 —— 视频纹理解耦后体验差，否决。

## 后果

- 优点：范围清晰、可测、与视频配套。  
- 代价：无法覆盖游戏向声音设计；不承诺引擎内补特效里程碑。

## 学习提示

1. 「增益混合」≠「特效」：音量相加是输出，EQ/混响才是特效。  
2. 注意回调线程与主线程的缓冲交换，避免欠载爆音。  
3. 与视频对齐时先统一时钟，再谈精密 A/V sync。
